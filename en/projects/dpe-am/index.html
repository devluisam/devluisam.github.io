Case study

How it was built

The problem, the architecture decisions and the technical challenges along the way.

Problem

A public exam syllabus is too big to fit a fixed schedule. Any plan made on Monday is wrong by Wednesday: you did badly on a mock exam, a review came due, a new topic appeared. The hard question isn’t “should I study?”, it’s “what should I study now?”.

Solution

Instead of a schedule, an adaptive priority queue, recalculated every time the dashboard opens and after any relevant event — with every factor visible, so the decision isn’t a black box.

The prioritization algorithm

priority = syllabus_weight   (0.30)
         × weakness         (0.30)   ← real performance on questions
         × urgency          (0.15)   ← days left until the exam
         × review_overdue   (0.15)
         × coverage_gap     (0.10)
         × novelty_bonus
         with a minimum floor, so a weak subject NEVER leaves the queue

Pure functions: no I/O, no hidden clock — and therefore testable.

Technical challenges

  • Making the rule testable.The domain/ layer never touches the database or the system clock; the services layer orchestrates Prisma. That made it possible to cover the formula, FSRS and metrics with real tests.
  • Keeping the algorithm from abandoning hard subjects.Multiplying factors tends to zero out items that score badly on every criterion; a floor keeps them showing up.
  • Detecting the official notice on its own.A monitor follows official sources, classifies documents and compares versions with a diff engine, showing what changed between publications.
  • Fixed time zone.All dates run on America/Manaus, so the system’s “today” never drifts.

My role

The whole project: the prioritization formula, an FSRS implementation for spaced review, an error log with pattern detection, mock exams in the official format, a readiness index, database modeling, interface and tests.

Outcome

A system in use: 33 models in the schema, 65 tests (46 domain and 19 integration with disposable SQLite), an installable PWA that works offline and full JSON backup.

Private repository — it contains study material and personal performance data.
