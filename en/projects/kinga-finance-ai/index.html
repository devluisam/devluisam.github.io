Kinga Finance AI

Financial analysis for a small retailer with several stores and a factory: it imports sales and costs, classifies expenses on its own and shows results per unit. Classification is a deterministic rules engine, with no language model — auditable and reproducible, which is what the case required.

Case study

How it was built

The problem, the architecture decisions and the technical challenges along the way.

Problem

Small retailers close the month in a spreadsheet. The owner knows how much came in, but not how much profit each store made, which cost category grew, or whether the month will end in the black before it’s over. The data exists — it’s just loose, uncategorized.

Solution

A system that takes in the records, categorizes each cost automatically, consolidates results per unit and turns it into a dashboard with an end-of-month forecast, a cost ranking and alerts for anything out of the ordinary.

Architecture

Dashboard (Streamlit + Plotly)
        │  HTTP
        ↓
REST API (FastAPI)  ──  /sales · /costs · /stores · /report
        │
        ↓
Domain modules — plain Python, no framework
   classifier · results · costs · billing · factory · forecast · health · alerts
        │
        ↓
SQLAlchemy 2 ──→ SQLite (default) or PostgreSQL

Technical challenges

  • Categorizing free-text expenses, without ML.A keyword rules engine that returns category, subcategory and a confidence level proportional to the recognized terms — with manual override when it gets it wrong. Predictable and explainable, unlike a trained classifier.
  • A single calculation core.The domain modules know nothing about FastAPI or Streamlit: they receive a session and return dataclasses. The same calculation feeds the API, the dashboard and the terminal report.
  • Financial health indexweighted across margin, growth, cost control and results, turned into a single number the owner understands.

My role

The whole project: modeling, API, classification engine, financial calculations (results per store, forecast, Pareto, alerts) and the dashboard.

Outcome

API, dashboard and terminal report sharing the same business rules, with automatic database backup on every start and CSV import.
