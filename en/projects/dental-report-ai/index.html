Case study

How it was built

The problem, the architecture decisions and the technical challenges along the way.

Problem

The clinic’s internship report is assembled from paper forms: patient data, treatment status and a count of each procedure. Transcribing it by hand is slow, repetitive and easy to get wrong in the totals — and the error only shows up after it has been handed in.

Solution

The student photographs the forms; the system reads the images, structures the data and assembles the report. Everything stays editable before export: automation speeds up the work, but the final word belongs to whoever signs the document.

Architecture

Photo upload
   │
   ├─ Path A ──→ POST /api/extract ──→ Claude (vision) ──→ structured JSON
   │                 (the API key stays on the server)
   │
   └─ Path B ──→ Tesseract.js in the client ──→ custom parser ──→ structured JSON
                              │
                              ↓
        Editable forms (React Hook Form + Zod)  ← human review
                              ↓
        A4 preview ──→ html2canvas ──→ jsPDF ──→ PDF

Technical challenges

  • Reading handwritten forms with an irregular layout.Generic OCR returns scrambled text. I wrote a parser specific to this form: label-based search, accent and case normalization, and reading the next meaningful line when the value isn’t on the same line as its label.
  • Not blindly trusting the extraction.Every extracted field is validated with Zod and goes into a reviewable form.
  • A PDF faithful to the screen— the preview is the document itself, captured and paginated as A4.

My role

The whole project: upload flow, server-side Claude API integration, OCR parser, forms, preview and PDF generation.

Outcome

A complete flow from upload to PDF, with two independent extraction paths and the credential never exposed to the browser.
